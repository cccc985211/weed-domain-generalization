# EXP-001: local environment + data/label audit + literature audit + 2-epoch smoke test

**Do not execute full training in this task.** Start by locating datasets using the human-provided local paths; never download 8GB+ archives without asking. Use a separate output directory for derived annotations and reports.

## Step A: environment capture
- Record OS, GPU/VRAM, driver, CUDA runtime, torch, torchvision, Ultralytics, Python, Git commit, environment list; check CUDA tensor and a one-batch YOLO11n forward.
- On Windows prefer `workers=0` and guard `main()` under `if __name__ == '__main__':`. Do not silently upgrade all packages.

## Step B: dataset and label audit
- Enumerate actual image and YOLO/COCO annotation files, classes and counts for CornWeed and Weed-crop V2. Include dimensions and bounding box distribution (sizes, truncation, illegal coords).
- Compute file SHA-256 and perceptual duplicate candidates; include examples of near duplicates by manifest IDs, without publishing raw image pixels.
- Check whether crop/weed binary labels are complete and consistent. Propose `weed-only` primary conversion. Verify whether maize/other crop boxes can be ignored as background without making other unannotated weeds systematic false negatives.
- Examine whether split-by-field/date/video groups is possible; if not, describe the risk, choose deterministic group-based surrogate with hashes and present manifest proposal for approval.
- Metadata-only inspection of target dataset is allowed for schema audit; do not calculate or reveal target test performance to inform method design.

## Step C: literature matrix
- Compile ≥10 real relevant papers with links/DOIs, year, problem, modules, evaluation protocol, similarities to A/B/C, and substantive gaps. Must include OA-DG (AAAI 2024) and DSD-YOLOv11 (Electronics 2026). Do not hallucinate citations.
- Make explicit GO/NO-GO recommendation for three-module novelty with evidence.

## Step D: model-selection smoke test (updated 2026-11-02)
- Model roster: **YOLO26n = primary research candidate**, **YOLO11n = historical baseline**, **YOLO26s = stronger baseline**. First check whether the installed Ultralytics supports YOLO26 and record exact versions/dependencies.
- After the dataset audit is accepted (or, provisionally, on a documented deterministic placeholder split), train `yolo26n.pt`, `yolo11n.pt` and `yolo26s.pt` for AT MOST 2 epochs each on the SAME split, `imgsz=640`, `seed=42`, `workers=0`, one GPU, aligned optimizer/hyperparameters where the trainer allows. Stop if dataset path or split is missing or suspicious.
- Record per model: wall time, peak GPU memory, train/forward/backward health, validation metrics (mAP50, mAP50:95, recall — **not** to be read as an accuracy ranking), and model output structure (head type, dual-head/one-to-one outputs, export shape).
- Analyze overlap of modules A/B/C with YOLO26's Progressive Loss and STAL, and whether module C can attach to YOLO26 with minimal code change.
- Do not start formal training. Write all model-selection outputs to `reports/EXP-001/model_selection/` and stop for review.
